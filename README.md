# StepperDriver: сервисная утилита

Утилита с графическим интерфейсом (PySide6, интерфейс на английском) для обслуживания плат StepperDriver через UART / RS-485:

- управление осями по протоколу платы: состояние по `GET_FEEDBACK` каждые 50 мс, питание, ходы, толчок, стоп, установка позиции, хоминг, групповые ходы;
- поиск плат на шине по диапазону ID;
- смена ID платы (команда `CHANGE_ID_DEVICE`, 250);
- перепрошивка: перевод платы в системный загрузчик STM32 командой `JUMP_TO_BOOTLOADER` (255), стирание, запись, проверка и запуск новой прошивки.

Прошивка идёт через встроенный загрузчик STM32 (протокол ST AN3155) по тому же USART1 и той же линии RS-485. Для этого нужен трансивер с автоматическим переключением направления: загрузчик STM32 не умеет управлять пином DE.

## Установка и запуск

```bash
cd tools/board_tool
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python board_tool.py
```

Windows: `.venv\Scripts\python board_tool.py`.

Linux: если порт `/dev/ttyUSB0` не открывается, добавьте пользователя в группу `dialout` (`sudo usermod -aG dialout $USER`) и перелогиньтесь.

## Управление осями

Вкладка **Control**: укажите Board ID и нажмите **Connect**. Пока управление подключено, утилита держит порт:

- `GET_FEEDBACK` каждые 50 мс: состояние, ошибка, позиция, обратная связь, рассогласование, скорость, признаки moving и at target, концевики;
- `GET_STATUS` раз в 10 опросов: питание (power) и «дом» (homed) есть только в нём;
- между опросами — команды из очереди.

Частота ответов показана рядом с кнопкой. Если плата не ответила на 10 опросов подряд, там будет «no reply from board».

| Кнопка | Команда | Когда утилита её отправляет |
|---|---|---|
| Power: On / Off | `POWER_ENABLE` (1) | всегда |
| Jog: ◀ − / + ▶ | `MOVE_CONTINUE` (4), при отпускании — `HALT` (6) | STANDSTILL, CONTINUE_MOTION, STOPPING |
| Move: Abs / Rel | `MOVE_ABSOLUTE` (3) / `MOVE_RELATIVE` (2) | STANDSTILL или DISCRETE_MOTION |
| Stop | `HALT` (6) с торможением из параметров | всегда |
| **E-STOP**, Esc | `EMERGENCY_STOP` (7), на все оси | всегда |
| Set position: Set | `SET_POSITION` (8) | ось не движется |
| Home: Start | `MOVE_HOME` (5): режим в `direction`, позиция дома в `position` | STANDSTILL |
| Abs all / Rel all | `MOVE_ABSOLUTE` / `MOVE_RELATIVE` с `axis_id = 3` | все три оси в STANDSTILL |
| Reset errors | `RESET_ERROR` (30) | всегда |

Прошивка молча игнорирует команду в неподходящем состоянии, поэтому утилита проверяет состояние по последнему опросу заранее и пишет причину отказа в журнал. Параметры Speed, Accel и Decel общие для всех команд, как и в `CommandData`.

**Выключение питания в движении.** Прошивка сначала тормозит ось и только потом выключает драйвер: STOPPING → DISABLED. Торможение берётся из текущего профиля: у хода — его Decel, у толчка — Accel, у хоминга — его торможение; если там 0, то 1000 шаг/с². Питание в статусе гаснет сразу. Пока ось тормозит, толчок, ходы и хоминг утилита не отправляет — прошивка их всё равно не примет. «Power on» во время этого торможения отменяет выключение: ось остановится и останется включённой. Нужна прошивка с этой логикой; старая включала драйвер обратно после остановки.

**E-STOP.** Аварийная остановка: прошивка сразу останавливает все оси без торможения, выключает драйверы и переводит оси в ERROR с ошибкой «emergency stop». Позиция после этого может не совпадать с реальной. Чтобы продолжить: **Reset errors** (оси перейдут в DISABLED), затем **Power on**. Кнопка и Esc работают и в главном окне, и в окне графиков.

Если плата не подтвердила `EMERGENCY_STOP` — нет ответа, например в старой прошивке без этой команды, — утилита сразу отправляет `HALT` на все оси и пишет об этом в журнал.

**Номер транзакции.** `AxesManager` отбрасывает команду, если её `transaction_id` совпадает с предыдущим. Поэтому при подключении утилита читает текущий номер из `GET_STATUS` и продолжает с него. Если ответ на команду потерялся, она повторяется до трёх раз с тем же номером, и плата не выполнит её дважды.

**Смена ID, прошивка, поиск.** На время этих операций опрос ставится на паузу, потому что им нужен порт. После смены ID опрос продолжается уже по новому ID. После прошивки — по ID, который вернула плата: после стирания всей flash это 1. После неудачной прошивки опрос не возобновляется: плата может остаться в загрузчике, и её кадры для загрузчика — мусор. Подключитесь вручную, когда плата снова отвечает. Клик по плате в таблице поиска переключает управление на неё.

**Безопасность.** В прошивке нет сторожевого таймера связи: ось в непрерывном движении (толчок, хоминг) остановится только по команде. Поэтому утилита:
- отправляет `HALT` при отпускании кнопки толчка;
- отправляет `HALT` на все оси при отключении, если какая-то ось в CONTINUE_MOTION или HOMING. Именно `HALT`, а не E-STOP: драйверы остаются включёнными, позиция не теряется;
- закрывает окно только через отключение.

Если утилита аварийно завершится или пропадёт кабель во время толчка, ось продолжит ехать до концевика.

**Нагрузка на шину.** Ответ `GET_FEEDBACK` — 87 байт, на 115200 бод это около 7,5 мс, то есть примерно 15 % времени линии при опросе каждые 50 мс. В текущей прошивке на время отправки ответа блокируется `loop()`, а в нём же читаются концевики.

## График

Галочка **Plot** на вкладке Control открывает отдельное окно с тремя графиками по времени:

| График | Сплошная линия | Пунктир (галочка «Feedback») |
|---|---|---|
| Position, steps | позиция планировщика (`position`) | обратная связь (`feedbackPos`) |
| Speed, steps/s | скорость планировщика (`velocity`) | обратная связь (`velocityFeedback`) |
| Lag error, steps | рассогласование: позиция планировщика минус выданные шаги | — |

Цвет линии — ось: X синяя, Y зелёная, C оранжевая. Галочками сверху скрываются оси и целые графики.

- **Window** — сколько секунд видно: 10 с … 5 мин или вся запись (All).
- **Sample every** — как часто опрашивать плату, пока окно открыто: 50, 20 или 10 мс. На 115200 бод ответ `GET_FEEDBACK` идёт около 8 мс, поэтому 10 мс — предел, и шина почти всё время занята. Когда окно закрыто, опрос возвращается к 50 мс. При запуске всегда 50 мс.
- **Pause** — графики останавливаются, запись продолжается. В паузе мышью выделяется участок по времени: он приближается сразу на всех графиках. Правая кнопка отдаляет, **Reset zoom** возвращает вид на момент паузы.
- Под графиками — значения в точке под курсором мыши: время и величины по видимым осям.
- **Clear** удаляет запись, **Save CSV…** сохраняет её целиком: время и пять величин по каждой оси.
- **E-STOP** и Esc работают и в этом окне.

Запись ведётся всё время, пока идёт опрос, даже при закрытом окне. Поэтому, открыв график, вы видите уже накопленную историю. Хранятся последние 60 000 отсчётов: 50 мин при опросе раз в 50 мс, 10 мин — раз в 10 мс. При смене Board ID запись начинается заново.

Время отсчёта — момент отправки запроса `GET_FEEDBACK`, а не момент, когда ответ дошёл до окна. Поэтому задержки интерфейса график не искажают.

Опрос раз в 50 мс — это 20 точек в секунду: короткий разгон в 0,1 с попадёт на график двумя-тремя точками. Чтобы рассмотреть форму профиля, ставьте 10–20 мс.

## Первая прошивка

В новой плате ещё нет протокола, поэтому первый раз она прошивается из PlatformIO (`pio run -t upload` через ST-Link или DFU).

Можно и этой утилитой, без PlatformIO:
1. поставьте перемычку BOOT0 = 1 и перезапустите плату;
2. на вкладке **Firmware** отметьте «Board is already in bootloader» и нажмите **Flash**;
3. снимите перемычку BOOT0.

ID новой платы — 1. Подключайте новые платы к шине по одной и сразу меняйте им ID: две платы с одинаковым ID отвечают одновременно и мешают друг другу.

## Смена ID

1. Вкладка **Board ID**, **Search** — опросить ID из диапазона. Клик по строке подставляет ID в поля.
2. Указать New ID (1…254) и нажать **Change ID**.

Перед сменой утилита проверяет, что плата отвечает, новый ID свободен и оси стоят. После команды плата пишет ID во flash (эмуляция EEPROM) и 1–2 с не отвечает. Утилита ждёт, пока плата откликнется по новому ID.

## Перепрошивка

Файл — `.pio/build/<env>/firmware.bin` (подставляется автоматически, если найден) или `.hex`.

Что происходит после нажатия **Flash**:

1. По протоколу платы (8N1): проверка связи и того, что оси стоят, затем команда `JUMP_TO_BOOTLOADER`.
2. Порт переключается в 8E1, синхронизация с загрузчиком (0x7F), определение МК.
3. Стирание:
   - **Firmware sectors only** (по умолчанию, STM32F2/F4). Последний сектор flash, где STM32duino хранит EEPROM с ID, не трогается, поэтому ID сохраняется;
   - **Whole flash** — для других МК или по желанию. ID сбросится на 1.
4. Запись блоками по 256 байт, затем проверка чтением, если включена.
5. Команда Go, порт обратно в 8N1, проверка, что новая прошивка отвечает.

Утилита откажется прошивать, если файл не помещается во flash или заходит в последний сектор (EEPROM). Такая прошивка сломалась бы при первой записи ID.

### Если прошивка прервалась

Пока питание не пропало, плата остаётся в загрузчике. Запустите прошивку снова с галочкой «Board is already in bootloader».

Если питание пропало после стирания, рабочей программы на плате нет. Поставьте BOOT0 = 1, перезапустите плату и прошейте с той же галочкой.

## Совместимость с прошивкой

- Команде `JUMP_TO_BOOTLOADER` утилита передаёт 4 байта ключа `0xB007C0DE` (little-endian). Текущая прошивка данные игнорирует и сразу уходит в загрузчик. Если в прошивке появится проверка ключа и подтверждение (пример `handleJumpToBootloader()`), утилита с ней тоже работает.
- Тест `tests/test_protocol_compat.py` собирает `src/CommandManager.cpp` прошивки на ПК и сверяет формат кадров и `StatusData`. Если протокол в прошивке изменится, тест это покажет. Путь к проекту прошивки задаётся переменной `STEPPERDRIVER_FIRMWARE` (см. «Тесты»).

## Если не получается

| Симптом | Что проверить |
|---|---|
| «STM32 bootloader does not answer 0x7F» | Попробуйте скорость загрузчика 57600. Если плата так и не уходит в загрузчик, добавьте в `jumpToBootloader()` остановку таймеров, `HAL_RCC_DeInit()` и remap системной памяти. Запасной путь — BOOT0. |
| «Adapter echo does not match» / ответы не разбираются | Галочка **Adapter echo**: отметьте её, если USB-RS485 адаптер возвращает в порт собственную передачу, иначе снимите. |
| Плата не находится поиском | Скорость порта (по умолчанию 115200), A/B линии, второе устройство с тем же ID. |

## Тесты

```bash
.venv/bin/pip install pytest
.venv/bin/python -m pytest tests
```

Сверка протокола с исходниками прошивки (`tests/test_protocol_compat.py`) запускается, только если указан проект прошивки, и требует `g++`:

```bash
STEPPERDRIVER_FIRMWARE=~/StepperDriver .venv/bin/python -m pytest tests
```

Без переменной этот тест пропускается (`skipped`), остальные работают как обычно. Самой утилите исходники прошивки не нужны.

Окно графиков проверяется без экрана (`QT_QPA_PLATFORM=offscreen` ставится в самом тесте).

Сценарии прогоняются на эмуляторе платы (`tests/board_emulator.py`): протокол прошивки с моделью осей (правила `AxisControl` и `AxesManager`, отбрасывание повторного `transaction_id`), загрузчик AN3155, flash F4 с секторами и EEPROM-ID. Эмулятор считает мусором байты с неверной скоростью или чётностью, поэтому ошибки переключения 8N1/8E1 тоже ловятся.
